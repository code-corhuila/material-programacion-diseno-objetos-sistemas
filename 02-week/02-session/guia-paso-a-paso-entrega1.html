1 Identificar las Entidades del Dominio

Lo primero es leer la descripción de tu proyecto asignado y listar todas las entidades (clases) que necesitas. Tu proyecto ya tiene entidades mínimas definidas, pero puedes agregar más si lo consideras necesario.

¿Cómo identificar entidades?

  • Lee la descripción del proyecto y subraya los sustantivos importantes
  • Cada sustantivo que represente un concepto del sistema es una posible clase
  • Identifica cuál es la clase abstracta (la clase padre general)
  • Identifica cuáles son las subclases (heredan de la abstracta)

Ejemplo: Sistema de Biblioteca Digital

De la descripción: "Sistema para gestionar el catálogo de una biblioteca digital: libros, revistas, audiolibros. Permite préstamos digitales, reservas, gestión de usuarios y notificaciones."

Entidad Tipo Justificación
RecursoDigital Clase abstracta Concepto general que agrupa libros, revistas y audiolibros
Libro Clase concreta (hereda de RecursoDigital) Tipo específico de recurso con ISBN, autor, páginas
Revista Clase concreta (hereda de RecursoDigital) Tipo específico con número de edición, periodicidad
Audiolibro Clase concreta (hereda de RecursoDigital) Tipo específico con duración, narrador
Usuario Clase concreta Persona que usa el sistema: solicita préstamos, hace reservas
Prestamo Clase concreta Relación entre usuario y recurso: fecha, estado, devolución
Reserva Clase concreta Reserva anticipada de un recurso por un usuario
Notificacion Clase concreta Mensaje al usuario por vencimiento, disponibilidad, etc.

✅ Resultado del Paso 1

Tienes una lista clara de al menos 6 entidades (clases), sabes cuál es la clase abstracta y cuáles son sus subclases.

3 Identificar Relaciones y Multiplicidad

Ahora debes definir cómo se conectan las clases entre sí. Tu proyecto debe tener al menos 3 tipos de relación diferentes.

Tipos de Relación — Repaso Rápido

Relación Símbolo UML Significado Pregunta Clave
Herencia ───▷ (flecha hueca) "es un tipo de" ¿Libro es un tipo de RecursoDigital? → SÍ
Composición ◆─── (rombo lleno) "contiene y no puede existir sin" ¿Un Préstamo existe sin un Usuario? → NO
Agregación ◇─── (rombo vacío) "contiene pero puede existir sin" ¿Un Usuario existe sin un Préstamo? → SÍ
Asociación ───── (línea simple) "se relaciona con" ¿Usuario se relaciona con Notificacion?
Dependencia - - -→ (línea punteada) "usa temporalmente" ¿Una clase usa a otra solo en un método?

Ejemplo: Relaciones del Sistema de Biblioteca Digital

Clase A Relación Clase B Multiplicidad Justificación
Libro, Revista, Audiolibro Herencia ───▷ RecursoDigital — Libro "es un" RecursoDigital
Prestamo Composición ◆─── Usuario 1 Usuario ←→ 0..* Prestamos Un préstamo no existe sin un usuario. Un usuario puede tener muchos préstamos
Prestamo Composición ◆─── RecursoDigital 1 Recurso ←→ 0..* Prestamos Un préstamo siempre tiene un recurso asociado
Reserva Composición ◆─── Usuario 1 Usuario ←→ 0..* Reservas Una reserva necesita un usuario
Reserva Composición ◆─── RecursoDigital 1 Recurso ←→ 0..* Reservas Una reserva necesita un recurso
Notificacion Asociación ───── Usuario 1 Usuario ←→ 0..* Notificaciones Un usuario recibe notificaciones

📌 Cómo definir la Multiplicidad

Hazte estas preguntas para cada relación:

  • ¿Cuántos B puede tener un A? → Eso va al lado de B
  • ¿Cuántos A puede tener un B? → Eso va al lado de A
  • Ejemplo: Un Usuario puede tener 0 o muchos Préstamos (0..*). Un Préstamo pertenece a exactamente 1 Usuario (1).

✅ Resultado del Paso 3

Tienes una tabla clara con todas las relaciones entre tus clases, el tipo de relación y la multiplicidad. Usas al menos 3 tipos de relación diferentes (herencia, composición, asociación, etc.).

  1. Abre app.diagrams.net
  2. Selecciona "Create New Diagram" → elige "UML" como categoría
  3. En la barra lateral izquierda, busca la sección UML
  4. Arrastra el bloque "Class" al lienzo por cada entidad
  5. Escribe nombre de clase, atributos y métodos con su visibilidad
  6. Usa los conectores UML para las relaciones (herencia, composición, etc.)
  7. Añade la multiplicidad escribiendo sobre las líneas de relación
  8. Exportar: File → Export as → PNG o SVG

📌 ¿Qué es un paquete en Java?

Un paquete (package) es una forma de organizar las clases relacionadas. La estructura de carpetas refleja la jerarquía de paquetes. Por ejemplo, la carpeta com/biblioteca/model/ corresponde al paquete com.biblioteca.model.

Cómo crear la estructura

Si usas un IDE como IntelliJ IDEA o VS Code con extensiones de Java:

  1. Crea un nuevo proyecto Java
  2. Dentro de src, crea los paquetes: com.biblioteca.model
  3. Crea cada archivo .java dentro del paquete correspondiente

Si prefieres hacerlo manualmente desde la terminal:

# Crear la estructura de carpetas
mkdir -p biblioteca-digital-grupo-1/diagrams
mkdir -p biblioteca-digital-grupo-1/src/com/biblioteca/model

# Crear los archivos vacíos
cd biblioteca-digital-grupo-1/src/com/biblioteca/model
touch RecursoDigital.java Libro.java Revista.java Audiolibro.java
touch Usuario.java Prestamo.java Reserva.java Notificacion.java

cd ../
touch Main.java

Paso 6 — Implementar las Clases Base en Java

Traducir el diagrama UML a código con atributos, constructores, getters y setters

📌 ¿Qué implementar en esta entrega?

Para la Entrega 1 debes crear las clases con:

  • Declaración de la clase con el paquete correcto
  • Atributos privados (o protegidos en la clase abstracta)
  • Constructor que inicialice todos los atributos
  • Getters y Setters según corresponda
  • Método toString() para representación textual

6.1 — Clase Abstracta: RecursoDigital.java

Esta es la clase padre de la cual heredarán Libro, Revista y Audiolibro.

package com.biblioteca.model;

/**
 * Clase abstracta que representa un recurso digital genérico
 * en la biblioteca.
 */
public abstract class RecursoDigital {

    // Atributos protegidos para que las subclases puedan acceder
    protected int id;
    protected String titulo;
    protected int anioPublicacion;
    protected boolean disponible;

    // Constructor
    public RecursoDigital(int id, String titulo, int anioPublicacion) {
        this.id = id;
        this.titulo = titulo;
        this.anioPublicacion = anioPublicacion;
        this.disponible = true;
    }

    // Getters
    public int getId() {
        return id;
    }

    public String getTitulo() {
        return titulo;
    }

    public int getAnioPublicacion() {
        return anioPublicacion;
    }

    public boolean isDisponible() {
        return disponible;
    }

    // Setters
    public void setDisponible(boolean disponible) {
        this.disponible = disponible;
    }

    // Método abstracto: cada subclase lo implementa de forma diferente
    public abstract String mostrarInformacion();

    @Override
    public String toString() {
        return "RecursoDigital{id=" + id +
               ", titulo='" + titulo + '\'' +
               ", anio=" + anioPublicacion +
               ", disponible=" + disponible + '}';
    }
}

💡 ¿Por qué es abstract?

Porque no tiene sentido crear un "RecursoDigital" genérico. Siempre será un Libro, una Revista o un Audiolibro. La clase abstracta define lo común, y cada subclase agrega lo específico.

6.2 — Clase Concreta: Libro.java

Hereda de RecursoDigital y agrega atributos propios del libro.

package com.biblioteca.model;

public class Libro extends RecursoDigital {

    private String isbn;
    private String autor;
    private int numeroPaginas;
    private String genero;

    // Constructor: llama al constructor del padre con super()
    public Libro(int id, String titulo, int anioPublicacion,
                 String isbn, String autor, int numeroPaginas, String genero) {
        super(id, titulo, anioPublicacion);
        this.isbn = isbn;
        this.autor = autor;
        this.numeroPaginas = numeroPaginas;
        this.genero = genero;
    }

    // Getters
    public String getIsbn() {
        return isbn;
    }

    public String getAutor() {
        return autor;
    }

    public int getNumeroPaginas() {
        return numeroPaginas;
    }

    public String getGenero() {
        return genero;
    }

    // Setters
    public void setGenero(String genero) {
        this.genero = genero;
    }

    // Implementación del método abstracto del padre
    @Override
    public String mostrarInformacion() {
        return "Libro: " + titulo + " | Autor: " + autor +
               " | ISBN: " + isbn + " | Páginas: " + numeroPaginas +
               " | Género: " + genero +
               " | Año: " + anioPublicacion +
               " | Disponible: " + (disponible ? "Sí" : "No");
    }

    @Override
    public String toString() {
        return "Libro{isbn='" + isbn + "', autor='" + autor +
               "', titulo='" + titulo + "', paginas=" + numeroPaginas + '}';
    }
}

6.3 — Clase Concreta: Revista.java

package com.biblioteca.model;

public class Revista extends RecursoDigital {

    private int numeroEdicion;
    private String periodicidad;
    private String editorial;

    public Revista(int id, String titulo, int anioPublicacion,
                   int numeroEdicion, String periodicidad, String editorial) {
        super(id, titulo, anioPublicacion);
        this.numeroEdicion = numeroEdicion;
        this.periodicidad = periodicidad;
        this.editorial = editorial;
    }

    // Getters
    public int getNumeroEdicion() {
        return numeroEdicion;
    }

    public String getPeriodicidad() {
        return periodicidad;
    }

    public String getEditorial() {
        return editorial;
    }

    // Implementación del método abstracto
    @Override
    public String mostrarInformacion() {
        return "Revista: " + titulo + " | Edición #" + numeroEdicion +
               " | Periodicidad: " + periodicidad +
               " | Editorial: " + editorial +
               " | Año: " + anioPublicacion +

## 🔗 Explicación de Relaciones

### Herencia (──▷)
- **Libro**, **Revista** y **Audiolibro** heredan de **RecursoDigital** 
  (clase abstracta).
- Justificación: Los tres son tipos específicos de recurso digital que 
  comparten atributos comunes (id, título, año, disponibilidad) pero 
  difieren en sus atributos propios.

### Composición (◆───)
- **Prestamo** contiene un **Usuario** y un **RecursoDigital**.
  - Multiplicidad: 1 Usuario → 0..* Prestamos
- **Reserva** contiene un **Usuario** y un **RecursoDigital**.
  - Multiplicidad: 1 Usuario → 0..* Reservas
- Justificación: Un préstamo o reserva no tiene sentido sin un usuario 
  y un recurso asociado.

### Asociación (─────)
- **Notificacion** se asocia con **Usuario**.
  - Multiplicidad: 1 Usuario → 0..* Notificaciones
- Justificación: Las notificaciones se envían a un usuario, pero el 
  usuario puede existir sin notificaciones.
